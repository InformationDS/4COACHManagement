# AI 教练助手 v0.2 前端技术架构文档

> 日期：2026-06-25  
> 输入来源：`PRD_AI_COACH_ASSISTANT_V0.2.md`、当前 HTML 交互原型 `ai-coach-v02-prototype/index.html`  
> 目标平台：微信小程序  
> 文档范围：前端页面架构、设计风格、交互逻辑、组件边界、状态管理与实现注意事项  
> 不包含：云函数实现、数据库设计、模型 Prompt、真实语音识别服务接入方案

## 1. 设计目标与实现原则

### 1.1 产品目标

AI 教练助手 v0.2 是面向自由私人教练的 AI-first 微信小程序。第一版前端重点不是做完整后台，而是验证教练能否通过语音和简短对话完成高频工作，并在写入前通过确认卡安全确认业务数据。

第一版主链路：

```text
AI 语音 / 文本输入
→ AI 理解意图
→ 查询 / 追问 / 生成草稿
→ 写入类任务生成确认卡
→ 教练确认
→ 保存业务结果
→ 日程 / 学员详情回看
```

### 1.2 前端实现原则

- `AI助手` 是默认入口，`日程`、`学员`、`我的` 是兜底操作和数据回看页面。
- 所有写入类动作必须先进入确认卡，包括排课、训练方案、课程训练总结、完课扣减。
- 语音转写结果必须先进入输入框，允许教练修改后再发送；第一版不做录完自动发送。
- 学员端不开放，前端不得出现学员预约、学员确认、学员自助查看等入口。
- 课时资产属于敏感数据，AI 不允许直接修改课时余额；课时变动只能通过受控手动流程。
- 当前 HTML 原型只用于交互验证，正式实现必须使用小程序页面、组件和状态模型重建，不直接复用 Web DOM 逻辑。

## 2. 信息架构

### 2.1 Tab 结构

底部导航固定为：

```text
AI助手 | 日程 | 学员 | 我的
```

建议使用小程序 `custom-tab-bar`，保持文字型 Tab，不强制使用图标。原因是当前产品是工具型应用，文字 Tab 信息清晰，且可避免图标资产和对齐问题。

| Tab | 定位 | 第一版前端职责 |
| --- | --- | --- |
| AI助手 | 默认工作台 | 对话、语音输入、快捷指令、确认卡、结果卡 |
| 日程 | 时间管理 | 日 / 周 / 月视图、排课、课程详情、课程训练总结入口 |
| 学员 | 数据回看 | 学员列表、学员详情、课时、课程、总结、轻量统计、备注 |
| 我的 | 低频设置 | 教练账户、默认课时时长、动作库入口、轻量反馈 |

### 2.2 页面层级

建议页面结构：

```text
miniprogram/
  pages/
    coach/
      ai-assistant/
      lessons/
      lesson-detail/
      students/
      student-detail/
      training-summary-detail/
      settings/
      action-library/
      lesson-form/
```

实现建议：

- `ai-assistant`、`lessons`、`students`、`settings` 为 Tab 页面。
- `lesson-detail`、`student-detail`、`training-summary-detail`、`action-library`、`lesson-form` 为二级页面。
- 如果第一阶段开发速度优先，也可以在 `lessons` 和 `students` 内用局部状态切换详情视图；但正式小程序更建议二级页面，便于导航栈、分享限制、返回行为和页面缓存管理。

## 3. 视觉风格

### 3.1 风格关键词

```text
AI-first / 工具型 / 高信息密度 / 健身行动感 / 克制 / 可扫读
```

界面应像教练每天使用的工作台，而不是营销页或内容社区。视觉重点是清晰、紧凑、状态明确。

### 3.2 色彩

沿用当前原型和既有小程序风格：

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 品牌主色 | `#FF6B35` | 主要按钮、激活 Tab、关键动作 |
| 品牌深色 | `#CC4921` | 强调文字、次级品牌状态 |
| 品牌浅底 | `#FFF0E8` | 标签、轻量强调背景 |
| 主文字 | `#1A1A2E` | 标题、核心信息 |
| 次级文字 | `#6B7280` | 描述、辅助信息 |
| 弱文字 | `#9CA3AF` | 占位、低优先级状态 |
| 页面背景 | `#F0F2F5` | 全局背景 |
| 卡片背景 | `#FFFFFF` | 列表、卡片、弹层 |
| 成功 | `#2D9A4E` | 保存成功、已完成 |
| 警告 | `#F5A623` | 冲突、待补、风险提示 |
| 错误 | `#E74C3C` | 阻断、失败 |

### 3.3 布局与密度

- 页面背景使用浅灰，内容承载在白色卡片或列表中。
- 卡片圆角建议 `12rpx` 到 `24rpx`，不要使用过度圆润的营销式大卡。
- 列表行保持高信息密度：主标题、关键副标题、右侧状态标签。
- AI 首页的今日状态区可以使用深色背景，形成默认入口的明显识别。
- 页面内不使用大面积插画、渐变装饰、装饰性背景图。
- 固定底部输入区和自定义 Tab 必须处理 safe area。

## 5. 页面交互逻辑

### 5.1 AI 助手页

页面结构：

```text
今日状态区
AI 对话区
快捷指令横向滚动区
底部输入区
```

交互规则：

- 页面默认显示行动引导，不重复今日状态区的全部数据。
- 快捷指令点击后只是发送预置意图，不绕过 AI 流程。
- 快捷指令区必须支持横向滚动；在小程序中用 `scroll-view scroll-x` 实现。
- 底部输入区固定在 Tab 上方，包含文本框、语音按钮、发送按钮。
- 长按语音按钮进入录音态，松开后进入上传 / 转写态，转写结果写入输入框。
- 转写失败时保留已输入文本，提示改用文字输入或重试。

AI 响应类型：

| 类型 | 前端呈现 |
| --- | --- |
| 普通回答 | 文本气泡或轻量数据卡 |
| 追问 | AI 气泡 + 可选候选项 |
| 草稿卡 | 可编辑结构化卡片 |
| 确认卡 | 写入前确认，必须展示关键字段 |
| 结果卡 | 执行成功 / 失败结果 |

写入类任务必须先生成确认卡。前端确认时只提交 `confirmationId` 和用户修改后的必要字段，不信任 AI 文本描述作为执行依据。

### 5.2 日程页

日程页顶部使用分段切换：

```text
日 | 周 | 月
```

日视图：

- 展示当天课程列表。
- 每行展示时间、学员、训练主题或方案状态、课程状态或总结状态。
- 点击课程进入课程详情。
- 页面提供明确的 `排课` 按钮。
- 课程快捷动作保留 `标记完成`、`记录训练`、`取消`，复杂修改放入课程详情。

周视图：

- 横向为周一到周日，纵向为时间段。
- 现有课程占据时间块。
- 点击空白时间段进入排课表单。
- 排课表单中的 `学员`、`日期`、`开始时间`、`结束时间` 应使用选择器或列表，不使用纯自由输入。
- 时间粒度为 15 分钟。

月视图：

- 只做轻量概览。
- 日期格展示课程数量、未完成课程、待补总结数量。
- 点击日期进入该日的日视图。

课程详情：

- 展示学员、日期、时间、地点、状态、课时余额、课前训练方案、课程训练总结状态、备注、创建来源。
- 可进入记录训练、查看课程训练总结、修改课程信息、取消课程。
- 标记完成必须弹出完课确认卡，确认后才扣减课时。

### 5.3 学员页

学员 Tab 首页只展示学员列表，不直接铺出某个学员详情。

列表规则：

- 顶部搜索学员。
- 列表行展示姓名、剩余课时、最近课程、最近主题、状态标签。
- 点击学员进入学员详情。

学员详情分区：

```text
概览 | 课程 | 总结 | 数据 | 备注
```

课程分区：

- 使用课程卡片，不使用单行挤压式文本。
- 课程卡展示日期、主题、状态、总结状态。
- 点击课程卡进入课程详情或训练记录详情。
- 训练记录详情应展示课程绑定关系，课程训练总结第一版不允许重新绑定到其他课程。

课时管理：

- 课时余额和课时变动记录必须可查看。
- 充值、手动扣减应是手动操作，AI 不直接触发。
- 课时变动记录不可删除。

### 5.4 我的页

我的页只承担低频设置：

- 教练账户展示。
- 默认课时时长配置。
- 动作库管理入口。
- 关于与轻量反馈入口。

第一版不在我的页展示 AI 模型、AI 额度、语音服务配置、会员订阅、收入统计、多教练切换。

动作库管理：

- 系统动作只读。
- 自定义动作可新增、编辑、停用。
- 别名新增必须由用户确认。
- 动作归一结果应在课程训练总结确认卡中展示，不在动作库里自动沉淀。

## 6. 状态管理与数据流

### 6.1 推荐前端状态分层

```text
App 全局状态
- 当前教练身份
- 云环境与登录态
- Tab 选中状态

页面状态
- 当前视图（日/周/月）
- 当前选中日期
- 当前学员 / 课程
- 表单输入
- 语音状态
- AI 会话消息

服务端状态
- 学员
- 课程
- 课时记录
- 训练方案
- 课程训练总结
- 动作库
- AI 确认卡
```

### 6.2 AI 会话数据流

```text
用户输入 / 语音转写文本
→ ai-assistant 页面追加 user message
→ 调用 AI 编排接口
→ 返回 response type
→ 前端渲染消息或卡片
→ 如果是确认卡，用户确认后调用确认执行接口
→ 返回结果卡
```

前端注意事项：

- 当前会话消息可以先保存在页面状态中。
- 确认卡需要有明确状态：`pending`、`confirmed`、`cancelled`、`expired`、`failed`。
- 确认卡过期后前端必须禁用确认按钮。
- 重新进入页面时，如存在未完成确认卡，应从服务端重新读取状态，不能只信本地缓存。

### 6.3 表单与校验

手动排课表单字段：

```text
学员
日期
开始时间
结束时间
地点
课前训练方案
备注
消耗课时
```

前端基础校验：

- 学员必选。
- 日期必选。
- 开始时间必选。
- 结束时间必选且晚于开始时间。
- 消耗课时只能是 `0.5`、`1`、`1.5`、`2`。
- 课时余额为 0 时前端给出阻断提示。

最终校验必须以后端结果为准，尤其是时间冲突、课时余额、课程归属和确认卡状态。

## 7. 当前原型覆盖情况

当前 HTML 原型已经覆盖的交互：

- 四个 Tab 的基础框架。
- AI 首页今日状态区、对话区、快捷指令横向滚动、底部输入区。
- 长按语音模拟、转写后进入输入框、可修改后发送。
- 记录训练确认卡、排课确认卡、冲突阻断、确认后结果卡。
- 日程日 / 周 / 月视图雏形。
- 日视图课程详情、排课按钮。
- 周视图空白时段进入选项式排课表单。
- 学员列表进入详情，课程卡片进入训练记录。
- 我的页账户、默认课时时长、动作库入口。

当前原型未覆盖或仅部分覆盖，但 PRD 要求第一版正式实现需要考虑：

- 真实微信录音、授权、上传、转写失败重试。
- AI 编排接口、真实确认卡状态、确认卡 15 分钟过期。
- 草稿卡的字段级编辑。
- 训练方案确认卡。
- 完课确认卡与完课扣课时。
- 课程取消、修改课程时间地点备注。
- 课时充值、手动扣减、课时变动记录。
- 学员添加 / 编辑。
- 动作库搜索、新增、编辑、停用、别名冲突处理。
- 动作归一不确定时的候选选择与长期别名保存确认。
- 月视图完整状态展示。
- AI 异常状态的真实服务降级。
- 反馈表单。

因此，正式开发时不能把当前原型当作完整 PRD 验收范围，只能把它作为交互方向和页面布局参考。

## 8. 小程序实现注意事项

### 8.1 小程序组件对应关系

| 原型元素 | 小程序实现 |
| --- | --- |
| HTML fixed input bar | `view` fixed bottom + safe area |
| 横向快捷指令 | `scroll-view scroll-x` |
| 底部弹层 | 自定义 `bottom-sheet` 或 TDesign Popup |
| 文本输入 | `textarea` |
| 下拉选项 | `picker` 或自定义选择列表 |
| Tab 切换 | custom tabBar + page route |
| 分段控件 | 自定义 segmented component |

### 8.2 不建议直接迁移的 Web 行为

- 不使用 DOM 查询和事件代理作为正式实现方式。
- 不依赖 CSS `position: sticky`、复杂 hover、鼠标滚轮逻辑。
- 不使用浏览器 localStorage 作为业务状态来源。
- 不把 HTML 原型中的 mock AI 路由逻辑放入小程序端。

### 8.3 推荐开发顺序

1. 搭建四 Tab 和 custom tabBar。
2. 实现 AI 首页静态骨架、消息列表、输入栏、快捷指令。
3. 接入语音状态机，但先 mock 转写结果。
4. 实现日程日视图、课程详情、手动排课表单。
5. 实现学员列表、学员详情、课程卡和训练记录详情。
6. 接入 AI 编排接口和确认卡执行接口。
7. 补齐训练方案确认卡、课程训练总结确认卡、完课确认卡。
8. 补齐我的页动作库和默认课时时长。
9. 做真实设备验证和异常路径验证。

## 9. 验收重点

第一版前端验收应重点看：

- 打开小程序默认进入 AI 助手。
- 语音转写结果进入输入框，用户可修改后发送。
- 每个写入动作都有确认卡。
- 确认卡关键字段清晰，不只藏在自然语言中。
- 时间冲突、课时不足、同名学员、课程缺失不会直接保存成功。
- 日程页能完成查课、排课、进入课程详情、进入记录训练。
- 学员页能从列表进入详情，并通过课程卡查看对应训练记录。
- 我的页不出现 AI 模型、额度、会员、多教练等第一版不做内容。
- 所有主流程都只服务教练，不要求学员配合。
