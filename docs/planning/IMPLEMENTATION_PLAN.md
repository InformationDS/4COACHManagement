## Phase 5: 双向约课闭环 & 订阅消息

### 5.1 约课流程完整性
- [ ] 学员发起约课 → 推送教练 → 教练确认/取消 → 推送学员
- [ ] 教练主动排课 → 推送学员 → 学员确认/取消 → 推送教练
- [ ] 课程取消 → 推送对方
- [ ] 课程完成 → 自动扣减课时
- [ ] 课时不足时，学员约课页面提示，无法提交

### 5.2 订阅消息集成
- [ ] `sendSubscribeMsg` 云函数：封装微信 `subscribeMessage.send` API
- [ ] 各页面在关键操作前调用 `wx.requestSubscribeMessage` 获取用户授权
- [ ] 场景覆盖：
  - [ ] 学员发起约课 → 教练收到提醒
  - [ ] 教练确认约课 → 学员收到确认
  - [ ] 教练排课 → 学员收到排课通知
  - [ ] 学员确认排课 → 教练收到确认
  - [ ] 课程取消 → 对方收到通知
  - [ ] 训练记录发布 → 学员收到通知
  - [ ] 课时不足 → 学员端提示

### 5.3 时间冲突检测
- [ ] 学员约课时，检测所选时段是否与已有课程冲突
- [ ] 教练排课时，检测排课时间是否与已有课程冲突
- [ ] 冲突时前端阻止提交并提示

## Phase 6: AI 训练记录

- [ ] 调用微信 `RecorderManager` API 录音

- [ ] 返回识别文字文本
- [ ] 录音状态 UI（录音中波浪动画、识别中转圈）

### 6.2 AI 结构化解析 (`parseTrainingRecord` 云函数)
- [ ] 接收原始语音文字 + 课程上下文（学员名、日期、地点）
- [ ] 调用 LLM API（OpenAI / Claude / 国内模型），携带结构化 Prompt
- [ ] 要求 LLM 返回固定 JSON Schema：
  ```json
  {
    "body_parts": ["胸部"],
    "exercises": [
      {"name": "杠铃卧推", "sets": 4, "reps": 12, "weight": "60kg"}
    ],
    "notes": "状态不错，力量有进步"
  }
  ```
- [ ] 错误处理：API 超时重试、返回格式校验、降级为纯文本展示
- [ ] Token 用量日志记录（方便后续分析成本）

### 6.3 训练记录确认页 (`coach/training-record`)

- [ ] 训练部位多选标签（胸/背/腿/肩/手臂/核心/有氧/其他）

- [ ] 课堂备注文本框
- [ ] 原始语音文字折叠展示（备用校对）

## 风险 & 注意事项

| 风险 | 影响 | 缓解方案 |
|------|------|----------|
| 微信语音识别准确率不足 | AI 结构化效果差 | 保底允许教练手动编辑；原始文字保留备查 |
| LLM API 费用超预期 | 运营成本高 | 使用性价比高的模型（如 GPT-4o-mini）；设月预算上限 |
| 订阅消息用户未授权 | 通知触达率低 | 关键操作前引导授权；降级为小程序内红点提醒 |
| 小程序审核不通过 | 延期发布 | 避免涉及 UGC 内容审核风险；按微信规范开发 |
| 数据库复合查询缺索引 | 课程历史返回空 | 部署前在云开发控制台手动创建索引 |
