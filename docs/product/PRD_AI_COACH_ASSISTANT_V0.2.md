# AI 教练助手产品设计方案 v0.2

> 日期：2026-06-24  
> 状态：产品设计讨论稿  
> 范围：微信小程序 AI 教练助手产品设计  
> 产品边界：教练单人模式，不开放学员端  
> 用途：已确认内容可作为后续实现输入；后续迭代方向不作为第一版实现依据  
> 本文不包含：系统架构、数据库设计、云函数实现、代码实现方案

---

## 1. 执行摘要

AI 教练助手是一款面向自由私人教练的微信小程序。它以 AI 对话和语音输入为核心入口，帮助教练完成查课、查学员、排课、课前训练方案整理和课程训练总结生成。

第一版重点验证一件事：教练能否通过语音和简短对话完成日常管理，并在写入前通过确认卡安全确认业务数据。

文档标记规则：

| 标记 | 含义 |
| --- | --- |
| 已确认 | 可以进入后续实现设计 |
| 后续迭代 | 不作为第一版实现依据 |
| 第一版不做 | 明确排除，避免 scope creep |

## 2. 当前已确认边界

### 2.1 产品边界

| 项目 | 已确认内容 |
| --- | --- |
| 产品形态 | AI-first 的教练个人工作台 |
| 平台 | 微信小程序 |
| 用户 | 自由私人教练 |
| 使用模式 | 教练单人模式 |
| 学员端 | 第一版不开放 |
| 默认入口 | `AI助手` |
| 导航 | `AI助手 | 日程 | 学员 | 我的` |
| 输入方式 | 文本输入 + 长按语音输入 |
| 写入安全 | 所有写入动作必须经过确认卡 |

### 2.2 核心原则

- AI 首页是主入口，辅助页面用于复杂编辑、数据回看和 AI 不可用时的兜底操作。
- 语音转文字是第一版核心能力，不是附加能力。
- 语音转写结果先进入文本输入框，用户可修改后再发送。
- AI 不能直接写入业务数据；排课、训练方案、课程训练总结都必须经过确认卡。
- 课时资产类操作不开放给 AI，包括 AI 自动扣课时、修改课时余额、删除数据、自动通知学员。

## 3. 第一版产品范围

### 3.1 目标用户

核心用户是自由私人教练。

典型特征：

- 主要通过微信和学员沟通。
- 没有专门的助理或运营系统。
- 课程、课时、课前方案和课程总结容易散落在聊天记录、备忘录和表格里。
- 工作场景移动性强，经常在训练现场、路上或课间处理事务。
- 很多时候双手不方便长时间操作手机。

### 3.2 第一版核心任务

| 任务 | 已确认范围 |
| --- | --- |
| 查课 | 查询今日课程、下一节课、当天剩余课程 |
| 查学员 | 查询剩余课时、最近课程、最近课程总结 |
| 排课 | 通过 AI 或手动方式创建已确认课程 |
| 课前训练方案 | 为单节课整理训练主题、热身、主体动作和注意事项 |
| 记录训练 | 将课后口述内容整理为结构化课程训练总结 |
| 动作归一 | 通过默认动作库、用户自定义动作和别名，将原始动作名称归一为标准动作名称 |

### 3.3 第一版核心闭环

```text
排课
→ 课前训练方案
→ 上课
→ 语音补充课后实际情况
→ 生成课程训练总结确认卡
→ 教练确认
→ 保存课程训练总结
```

## 4. 信息架构与四个 Tab

底部导航：

```text
AI助手 | 日程 | 学员 | 我的
```

| Tab | 定位 | 第一版职责 |
| --- | --- | --- |
| AI助手 | 默认入口 | 自然语言对话、语音输入、快捷指令、卡片输出 |
| 日程 | 课程时间管理 | 日/周/月视图、排课、课程详情、完成/取消、课程总结入口 |
| 学员 | 学员数据回看 | 学员列表、搜索、详情、课时、历史课程和课程总结 |
| 我的 | 个人设置与动作库 | 教练资料、默认课时时长、动作库管理 |

辅助页面不追求完整后台化。第一版只保留 AI 工作台运行所需的业务兜底、结果回看和基础设置能力。

## 5. AI 首页

### 5.1 第一屏结构

AI 首页第一屏从上到下分为：

1. 今日状态区
2. AI 对话区
3. 快捷指令区
4. 底部输入区

### 5.2 今日状态区

今日状态区只做可扫一眼的数据摘要，不承担对话引导。

显示内容：

```text
今日 3 节课
下一节 14:00 小王
总结未完成 1 条
```

第一版不显示低课时提醒、运营复盘、复杂统计、长文本建议。

今日状态区不显示待确认 AI 草稿。确认卡、草稿卡和失败任务只在 AI 对话区中呈现。

### 5.3 AI 对话区默认开场

默认开场只做行动引导，不重复今日状态区数据。

示例：

```text
你可以直接说：记录刚才这节课的训练内容，或安排下一节课。
```

如果当天没有课程：

```text
今天还没有课程。你可以直接说“给小王明天下午三点排一节课”。
```

如果有总结未完成：

```text
你可以直接说“补一下刚才那节课的课程总结”。
```

### 5.4 快捷指令

快捷指令不是直接写入，也不绕过 AI。它发送预置意图，进入正常 AI 对话流程。

| 快捷指令 | 点击后执行 | 可能输出 |
| --- | --- | --- |
| 记录训练 | 进入课程训练总结流程，提示用户说或输入课后实际情况 | 追问卡、课程训练总结草稿卡、课程训练总结确认卡 |
| 安排课程 | 进入排课流程，提示输入学员和时间 | 追问卡、排课确认卡 |
| 查今日课表 | 执行只读查询 | 今日课程列表卡、普通文本回答 |
| 分析学员 | 先询问选择或输入学员 | 学员摘要、数据不足提示 |

`记录训练` 是用户可见入口文案；产品语义上进入的是课程训练总结流程。

### 5.5 底部输入区

底部输入区参考常见聊天产品：

```text
[ 和 AI 教练说点什么... ] [ 语音按钮 ]
```

交互规则：

- 中间是文本输入框。
- 右侧固定为语音输入按钮。
- 语音按钮采用长按录音。
- 长按语音期间支持上滑取消。
- 录音结束后先转文字。
- 转写文本填入输入框，用户可修改、补充、清空或发送。
- 第一版不做录完自动发送。

首次使用时提供轻量引导，提示用户长按语音按钮开始说话。引导只解释核心操作，不做复杂新手教程。

### 5.6 语音状态

语音输入状态：

| 状态 | 含义 |
| --- | --- |
| `idle` | 未录音 |
| `recording` | 录音中 |
| `uploading` | 上传中 |
| `transcribing` | 转写中 |
| `failed` | 转写失败 |

异常处理：

| 场景 | 产品处理 |
| --- | --- |
| 未授权麦克风 | 引导开启麦克风权限 |
| 录音太短 | 提示重新录音 |
| 录音太长 | 自动结束并提示 |
| 上传失败 | 提供重试或改用文字输入 |
| 转写失败 | 提示失败，保留文本输入 |
| 无法识别内容 | 提示重录或手动输入 |
| AI 后续失败 | 保留转写文本，不丢失输入内容 |

AI 首页异常状态规则：

- 不展示常驻语音权限或 AI 服务状态。
- 仅在异常发生时展示轻量提示，例如麦克风未授权、转写失败、AI 请求失败。
- 异常提示不进入我的 Tab 配置，也不占用今日状态区。

第一版录音限制：

- 最短录音：1 秒
- 最长录音：60 秒
- 语音转写失败后不长期保留原音频。

## 6. 日程 Tab

### 6.1 定位

日程 Tab 是课程时间管理和课程状态处理页面。它不是运营看板，也不是复杂后台。

日程 Tab 回答四个问题：

- 今天或某天有哪些课？
- 本周还有多少课已经完成，多少课待上？
- 哪些时间段可以排课？
- 某节课的课前训练方案和课程训练总结状态是什么？

### 6.2 视图切换

日程 Tab 顶部使用分段切换：

```text
日 | 周 | 月
```

| 视图 | 核心用途 | 第一版范围 |
| --- | --- | --- |
| 日视图 | 查看和处理当天课程 | 完整实现 |
| 周视图 | 查看一周课程分布，辅助排课 | 完整实现 |
| 月视图 | 查看月份课程概览，快速跳转日期 | 轻量实现 |

### 6.3 日视图

日视图用于查看和处理某一天的课程。页面应像课表一样紧凑展示，尽量让教练一屏看完整天课程。

状态栏：

```text
6月25日 周四 · 3节课
```

课程行示例：

```text
09:00-10:00  小王  胸肩方案  已确认
11:00-12:00  小李  下肢方案  已确认
14:00-15:15  张三  待补方案  已确认
18:30-19:30  小赵  已完成 · 总结未完成
```

每行只展示：

- 开始和结束时间
- 学员姓名
- 训练方案主题或方案状态
- 课程状态或课程训练总结状态

取消课程不混在正常课表中。日视图底部单独展示折叠区：

```text
已取消课程 2
14:00-15:00 小王
16:00-17:00 小李
```

### 6.4 周视图

周视图用于排课和查看一周课程负载。

周视图顶部状态栏只使用纯规则统计：

```text
本周 12 节课 · 已完成 3 节 · 待上课 9 节
```

统计口径：

| 指标 | 口径 |
| --- | --- |
| 本周课程数 | 本周未取消课程总数 |
| 已完成 | 状态为已完成的课程数 |
| 待上课 | 未取消且未完成的课程数 |

展示规则：

- 横向为周一到周日。
- 纵向为时间段。
- 时间粒度为 15 分钟。
- 已有课程占据对应时间块。
- 点击空白时间段默认打开手动新建课程。
- 空白时间段可提供 `问 AI 排课` 二级入口。
- 点击已有课程进入课程详情。
- 第一版不主动生成排课建议；智能排课建议放在 AI 助手中由用户主动询问。

### 6.5 月视图

月视图只做轻量概览，不承载复杂排课操作。

每个日期显示：

- 当天课程数量
- 未完成课程标记
- 课程训练总结未完成数量

示例：

```text
25
3节
总结未完成1
```

点击某天进入该日期的日视图。

第一版月视图不做每天展开课程详情、拖拽改期、批量排课、复杂统计。

### 6.6 状态规则

课程状态只包含：

| 状态 | 含义 |
| --- | --- |
| `已确认` | 已排课，尚未标记完成或取消 |
| `已完成` | 教练已确认完课 |
| `已取消` | 课程已取消，不再占用时间冲突 |

课程训练总结状态只包含：

| 状态 | 含义 |
| --- | --- |
| `未完成` | 该课程尚未保存课程训练总结 |
| `已完成` | 该课程已保存课程训练总结 |

产品规则：

- 课前训练方案是课程的可选内容，不属于课程训练总结状态。
- 教练可能不是每节课都会写课前训练方案。
- 课程已完成但课程训练总结未完成时，页面显示 `总结未完成`。
- 课程训练总结状态不使用其他复杂枚举。

### 6.7 课程快捷动作

课程行上的快捷动作只保留：

- 标记完成
- 记录训练
- 取消

| 课程状态 | 快捷动作 |
| --- | --- |
| 已确认 | 标记完成、记录训练、取消 |
| 已完成且无课程训练总结 | 记录训练 |
| 已完成且有课程训练总结 | 查看总结 |
| 已取消 | 不展示快捷动作 |

`修改课程` 不放在课程行快捷动作里，放在课程详情中。

标记完成规则：

- 点击 `标记完成` 后必须弹出完课确认卡。
- 完课确认卡中展示学员、课程时间、消耗课时、当前剩余课时和确认后剩余课时。
- 用户确认后，课程状态变为 `已完成`，并生成一条 `完课扣减` 课时变动记录。
- 用户取消后，课程状态和课时余额都不变。

取消课程规则：

- 点击 `取消` 后必须确认。
- 取消课程不扣课时。
- 取消课程释放时间冲突。
- 取消原因可选。
- 已取消课程保留在历史中，不混入正常课表，不展示快捷动作。

### 6.8 手动新建课程

手动新建课程是 AI 不可用或教练明确想手动操作时的兜底能力。

字段：

```text
学员
日期
开始时间
结束时间
地点
消耗课时
课前训练方案
备注
```

时间规则：

- 开始时间和结束时间都允许教练自由选择。
- 时间粒度为 15 分钟。
- 可以设置默认课时时长，用于新建课程时自动带出结束时间。
- 教练可以自由修改结束时间。
- 系统根据开始时间和结束时间自动计算课程时长。

消耗课时规则：

- 课程时长和消耗课时分离。
- 消耗课时默认值为 `1`。
- 教练可在排课时修改消耗课时。
- 第一版消耗课时取值限定为 `0.5`、`1`、`1.5`、`2`。
- 消耗课时用于完课确认后的课时扣减，不由课程时长自动推导。

校验规则：

- 学员必选。
- 日期必选。
- 开始时间必选。
- 结束时间必选，且必须晚于开始时间。
- 消耗课时必选。
- 学员剩余课时小于消耗课时时不允许排课。
- 与已有未取消课程冲突时不允许保存。

保存后课程状态为已确认。

### 6.9 课程详情

课程详情承载完整课程信息和低频操作。

详情字段：

```text
学员
日期
开始时间
结束时间
地点
状态
课时余额
消耗课时
课前训练方案
课程训练总结状态
备注
创建来源：AI / 手动
```

详情页可操作：

- 修改课程时间、地点、备注
- 修改消耗课时
- 修改课前训练方案
- 标记完成
- 记录训练
- 取消课程
- 查看课程训练总结

### 6.10 与 AI 助手联动

联动规则：

- AI 排课确认后，课程出现在日程视图。
- 日程页点击 `记录训练`，跳到 AI 助手，并带上课程上下文。
- 日程页点击某节课的训练方案，可让 AI 帮助整理方案。
- 日程页空状态可跳到 AI 助手发起排课。
- 日程页空白时间段默认打开手动新建课程，并提供 `问 AI 排课` 二级入口。

带上下文跳转示例：

```text
正在为小王 6月25日 14:00 这节课生成课程训练总结，请说课后实际情况。
```

## 7. 学员 Tab

### 7.1 定位

学员 Tab 是学员档案、课时、历史课程和课程训练总结的数据回看页面。它不是复杂 CRM，也不是学员端入口。

学员 Tab 回答四个问题：

- 这个学员是谁？
- 还剩多少课时？
- 最近上了什么课？
- 最近训练主题、课程总结和训练数据是什么？

### 7.2 学员列表

学员列表保持高信息密度，不使用过大的卡片。

列表行展示：

```text
丽姐
剩余 8 节
最近上课：6月22日
最近主题：上肢训练
```

列表顶部：

```text
搜索学员
[添加学员]
```

第一版列表标签：

- `低课时`
- `总结未完成`

标签规则：

- 剩余课时 `<= 2` 时显示 `低课时`。
- 存在已完成课程且课程训练总结状态为 `未完成` 时显示 `总结未完成`。
- `低课时` 只在学员列表和学员详情中展示，不进入 AI 首页今日状态区。

排序规则：

- 默认按最近上课时间倒序。
- 没有课程记录的新学员可显示 `新学员` 标记。

### 7.3 学员详情

学员详情第一屏展示：

```text
丽姐
剩余课时：8节
最近课程：6月22日 上肢训练
总结未完成：0
```

详情页使用分段 Tabs：

```text
概览 | 课程 | 总结 | 数据 | 备注
```

### 7.4 概览

概览展示事实摘要，不做复杂分析。

显示内容：

- 剩余课时
- 最近课程
- 最近课程训练总结
- 近 30 天课程数
- 最近训练主题

### 7.5 课程

课程分区展示该学员课程列表。

示例：

```text
6月22日 14:00 上肢训练 已完成
6月25日 15:00 下肢训练 已确认
```

点击课程进入课程详情。

### 7.6 总结

总结分区展示该学员所有课程训练总结。

示例：

```text
6月22日 第14节 上肢训练
```

## 8. 我的 Tab

### 8.1 定位

我的 Tab 是低频配置页，用于管理教练账户、全局默认课时时长和动作库。

我的 Tab 不承担高频业务操作，不做复杂个人中心，也不作为 AI 或语音能力的设置中心。

我的 Tab 回答三个问题：

- 当前登录的是哪个教练？
- 新建课程时默认预填多长时间？
- 训练动作如何维护标准名称和别名？

### 8.2 页面结构

我的 Tab 第一版从上到下分为：

1. 账户区

3. 动作库管理
4. 关于与帮助

账户区展示：

- 教练头像
- 教练昵称
- 当前身份：教练
- 微信授权状态

- 第一版只支持教练单人模式。
- 不展示会员、订阅、套餐、组织、多教练切换。
- 不在此处展示 AI 模型、AI 额度或语音服务配置。

### 8.4 默认设置

默认设置第一版只包含：

| 设置项 | 产品规则 |
| --- | --- |
| 默认课时时长 | 用于新建课程时预填结束时间 |

默认课时时长规则：

## 9. 课程训练总结模型

### 9.1 模型定义

真实私教工作中，教练可能会在上课前一天确认训练方案，上课后再根据实际表现补充闪光点、问题和总结。因此第一版将训练内容定义为绑定到单节课的 `课程训练总结`。

课程训练总结由两部分组成：

- 课前训练方案：上课前预计练什么。
- 课后实际总结：上课后实际完成了什么、表现如何、遇到什么问题、后续怎么改进。

展示上输出一份可读总结；数据上保留结构化字段，方便后续查询、对比和 AI 继续使用。

### 9.2 总体结构

```text
训练主题
课前训练方案
- 热身
- 主体训练动作
课后实际总结
- 实际动作完成情况
- 训练闪光点
- 力量强度
- 完成度
- 训练问题
- 今日总结
```

### 9.3 课程训练总结字段

| 字段 | 类型 | 取值范围 / 规则 |
| --- | --- | --- |
| `theme` | 文本 | 训练主题，例如 `上肢训练`、`胸 + 三头`；必填 |
| `warmup` | 文本或列表 | 热身内容；可为空 |
| `planned_actions` | 动作列表 | 课前方案动作；可为空 |
| `actual_actions` | 动作列表 | 课后实际动作；可为空 |
| `highlights` | 文本列表 | 本节课训练闪光点；可为空 |
| `intensity` | 枚举 | `低强度`、`中低强度`、`中强度`、`中高强度`、`高强度`、`未填写` |
| `completion_rate` | 数字或空 | 0-100 的整数百分比；未提及时为 `未填写` |
| `issues` | 问题列表 | 动作问题、发力问题、关节压力、教练提醒；可为空 |
| `final_summary` | 文本 | 今日总结；可为空 |

### 9.4 动作字段

| 字段 | 类型 | 取值范围 / 规则 |
| --- | --- | --- |
| `raw_name` | 文本 | 用户原始动作说法，必填，例如 `卧推`、`面拉` |
| `canonical_name` | 文本 | 标准动作名称，必填；用于训练数据分析、可视化和历史统计 |
| `normalization_status` | 枚举 | `exact`、`matched_from_plan`、`matched_alias`、`ai_inferred`、`ambiguous`、`unnormalized` |
| `planned_weight` | 文本或空 | 例如 `2kg`、`自重`；不强制数值化 |
| `planned_sets` | 数字或空 | 正整数 |
| `planned_reps` | 文本或空 | 例如 `15次`、`10-15次`、`力竭` |
| `actual_weight` | 文本或空 | 例如 `25kg`、`自重` |
| `actual_sets` | 数字或空 | 正整数 |
| `actual_reps` | 数字或空 | 正整数；未提及时为空 |
| `status` | 枚举 | `completed`、`modified`、`replaced`、`skipped`、`added`、`unknown` |
| `replaced_by` | 文本或空 | 当 `status = replaced` 时填写替换动作 |
| `reason` | 文本或空 | 调整、跳过或替换原因 |
| `notes` | 文本或空 | 动作提醒、发力问题或其他备注 |

### 9.5 动作名称归一规则

第一版必须内置默认动作库，并支持用户自定义动作和别名。训练数据分析、可视化和历史总结统一基于 `canonical_name`，不是基于用户原始输入。

动作库字段：

| 字段 | 规则 |
| --- | --- |
| `canonical_name` | 标准动作名称，必填 |
| `aliases` | 别名列表，可为空 |
| `body_part` | 训练部位，必填；取值：`胸`、`背`、`腿`、`肩`、`手臂`、`核心`、`全身`、`其他` |
| `equipment` | 器械，可为空；取值：`杠铃`、`哑铃`、`绳索`、`器械`、`自重`、`弹力带`、`壶铃`、`其他`、`未指定` |
| `movement_type` | 动作类型，可为空；取值：`推`、`拉`、`蹲`、`髋铰链`、`旋转`、`支撑`、`孤立`、`复合`、`有氧`、`其他` |
| `source` | `system` 或 `custom` |
| `notes` | 备注，可为空 |

默认动作库第一版规模：

- 覆盖常见私教训练动作。
- 按 `胸`、`背`、`腿`、`肩`、`手臂`、`核心`、`全身`、`其他` 分类。
- 每个主要部位覆盖约 10-20 个常见动作。
- 第一版总量控制在约 80-120 个标准动作。
- 默认动作库用于动作归一，不作为动作教学百科。

默认动作库示例：

| 标准动作名称 | 别名 | 训练部位 | 器械 |
| --- | --- | --- | --- |
| 杠铃卧推 | 卧推、平板卧推、杠铃平板卧推 | 胸 | 杠铃 |
| 哑铃卧推 | 哑铃平板卧推 | 胸 | 哑铃 |
| 坐姿面拉 | 面拉、坐姿绳索面拉 | 肩后束 / 上背 | 绳索 |
| 绳索直臂下压 | 直臂下压 | 背 | 绳索 |
| 哑铃俯身飞鸟 | 俯身飞鸟 | 肩后束 | 哑铃 |

归一优先级：

1. 匹配当前课程的课前训练方案。
2. 匹配用户自定义动作库和别名。
3. 匹配系统默认动作库和别名。
4. 结合训练部位、器械和上下文由 AI 推断。
5. 无法确定时追问，或在确认卡中要求教练选择。
6. 仍无法归一时保留原始名称，标记为 `unnormalized`。

归一状态：

| 状态 | 含义 |
| --- | --- |
| `exact` | 原始名称就是标准动作名称 |
| `matched_from_plan` | 根据课前训练方案匹配 |
| `matched_alias` | 根据动作库别名匹配 |
| `ai_inferred` | AI 根据部位、器械和上下文推断 |
| `ambiguous` | 存在多个候选，需要教练确认 |
| `unnormalized` | 无法归一，暂存原始名称 |

产品规则：

- 必须同时保存 `raw_name` 和 `canonical_name`。
- 用户自定义动作库优先于系统默认动作库。
- AI 不确定时不能强行合并动作。
- 确认卡必须展示可能出错的动作归一结果。
- 教练在确认卡中修改标准动作名后，该次保存使用修改后的 `canonical_name`。

用户自定义动作能力：

- 教练可以新增自定义动作。
- 教练可以编辑自定义动作的标准名称、别名、训练部位、器械和备注。
- 教练可以为系统内置动作或自定义动作添加别名。
- 教练可以删除未被历史课程训练总结引用的自定义动作。
- 已被历史课程训练总结引用的自定义动作不直接删除；第一版优先标记为停用，历史数据保留原 `canonical_name`。

别名冲突处理：

- 同一个别名命中多个标准动作时，AI 不能自动归一。
- 确认卡必须让教练选择标准动作名称。
- 用户可选择保留原始名称，状态标记为 `unnormalized`。
- 用户修正归一结果后，保存为长期别名必须单独确认。

### 9.6 动作状态枚举

| 状态 | 含义 |
| --- | --- |
| `completed` | 按方案完成，实际记录与方案一致或无关键差异 |
| `modified` | 做了同一动作，但重量、组数、次数、节奏或执行要求有变化 |
| `replaced` | 方案动作没有做，改成另一个动作 |
| `skipped` | 方案动作没有做，且没有替换动作 |
| `added` | 方案外新增动作 |
| `unknown` | 课后记录没有明确提到，不能判断完成情况 |

### 9.7 课前方案与课后实际的冲突处理

处理原则：

```text
课前方案不被课后实际覆盖
课后实际记录真实发生
AI 标记差异，不悄悄改方案
确认卡必须展示差异
```

| 冲突类型 | 处理方式 |
| --- | --- |
| 重量不同 | 保留 `planned_weight` 和 `actual_weight`，状态为 `modified` |
| 组数不同 | 保留 `planned_sets` 和 `actual_sets`，状态为 `modified` |
| 次数不同 | 保留 `planned_reps` 和 `actual_reps`，状态为 `modified` |
| 动作没做 | 原方案动作状态为 `skipped` |
| 动作替换 | 原方案动作状态为 `replaced`，填写 `replaced_by`；新动作作为 `added` 记录 |
| 方案外新增 | 新动作状态为 `added` |
| 课后没提到方案动作 | 状态为 `unknown`，不自动判断完成 |
| 实际记录含糊 | 先追问，不直接生成确认卡 |

需要追问的情况：

- 用户说“有几个动作没做”，但没说是哪几个。
- 用户说“改了动作”，但没说改成什么。
- 同一动作出现两个不同重量，无法判断哪个是实际完成值。
- 学员或课程无法确定。
- 课后实际与课前方案差异很大，但没有说明原因。

可为空的情况：

- 没有明确力量强度，显示 `未填写`。
- 没有明确完成度，显示 `未填写`。
- 没有今日总结，允许只保存结构化动作和问题。

保存规则：

- 课程训练总结第一版必须绑定到单节课程。
- 课程训练总结保存后不允许重新绑定到其他课程。
- 课后总结缺失强度或完成度时允许保存，对应字段为 `未填写`。
- 语音转写失败后不长期保留原音频。

### 9.8 结构化转换步骤

1. 识别学员和课程，确定要写入哪一节课。
2. 读取该课程已有的课前训练方案。
3. 将用户输入拆分为训练主题、实际动作、闪光点、强度、完成度、问题、今日总结。
4. 将动作描述归一到动作列表，保留 `raw_name`，并通过动作库得到 `canonical_name`。
5. 提取重量、组数、次数、备注。
6. 将实际动作和课前方案逐项对比。
7. 为每个动作标记状态：`completed`、`modified`、`replaced`、`skipped`、`added` 或 `unknown`。
8. 遇到动作归一歧义、关键冲突或无法判断的差异，先追问。
9. 生成结构化数据和展示文本。
10. 在确认卡中展示结构化结果、动作归一结果和方案差异。
11. 教练确认后保存。

课前训练方案入口：

- 课程详情中保留课前训练方案入口。
- AI 助手中保留通过自然语言生成或修改课前训练方案的入口。
- 课前训练方案必须绑定到单节课程。

### 9.9 展示文本格式

课程训练总结展示格式保持教练可读，不要求用户看到字段名。

```text
6.22 丽姐第14节课程总结

上肢训练

一、开背热身

二、主体训练
- 哑铃俯身飞鸟 2kg 4组x15次
- 坐姿面拉 25kg 4组x15次

三、本节课训练闪光点
- 坐姿面拉
- 本节课力量强度：中强度
- 本节课完成度：90%

四、本节课训练遇到的问题
- 面拉全程收紧核心、稳定躯干、沉肩
- 直臂下压避免手腕受压，以背部肌群主导发力

五、今日总结
本次训练专门针对上肢短板设计...
```

## 10. AI 核心能力与输出类型

### 10.1 第一版 AI 核心能力

| 能力 | 输入示例 | 输出 |
| --- | --- | --- |
| 查今日课表 | `我今天有哪些课？` | 今日课程列表卡或文本 |
| 语音排课 | `给小王明天下午三点排一节课` | 排课确认卡 |
| 课前训练方案 | `给小王明天这节课做胸和三头方案` | 训练方案确认卡 |
| 记录训练 | `丽姐今天坐姿面拉表现最好，中强度，完成度90%` | 课程训练总结确认卡 |
| 基础学员查询 | `小王还剩多少课时？` | 学员数据卡或文本 |

### 10.2 AI 输出类型

第一版只需要 5 类输出：

| 类型 | 用途 |
| --- | --- |
| 普通回答 | 只读查询和简单说明 |
| 追问 | 信息不足或存在歧义 |
| 草稿卡 | 已整理出结构化内容，但还需检查或补充 |
| 确认卡 | 写入前确认 |
| 结果卡 | 展示执行结果 |

### 10.3 写入类能力规则

- 排课、训练方案、课程训练总结、完课扣减都是写入类能力。
- 写入类能力必须生成确认卡。
- 前端展示确认卡，用户确认后才保存。
- 用户取消后不保存。
- 关键冲突无法判断时先追问，不生成确认卡。

## 11. 确认卡规则

### 11.1 通用规则

确认卡是 AI 写入业务数据前的最后一道人工确认。

所有确认卡必须满足：

1. 明确展示即将写入的数据。
2. 关键字段不能只藏在自然语言中。
3. 用户确认前允许修改。
4. 用户取消后不保存。
5. 确认卡超时后不能继续执行。
6. 执行前必须重新校验业务数据。

确认卡状态：

```text
pending     等待确认
confirmed   已确认并执行成功
cancelled   用户取消
expired     超时失效
failed      执行失败
```

确认卡有效期：15 分钟。

### 11.2 课程训练总结确认卡

确认卡必须展示：

- 学员
- 对应课程
- 训练主题
- 课前训练方案
- 方案与实际差异
- 课后总结
- 今日总结

差异区至少包含：

```text
按方案完成
有调整
跳过或替换
方案外新增
未确认
```

动作归一区至少展示：

```text
“卧推” 已识别为 “杠铃卧推”
“面拉” 已识别为 “坐姿面拉”
```

如果存在多个候选，确认卡必须要求教练选择标准动作名称。

产品规则：

- 找不到学员时，先追问，不出确认卡。
- 多个同名学员时，先让教练选择。
- 找不到对应课程时，先追问；第一版课程训练总结必须绑定到课程。
- 如果该课程已有课程训练总结，确认卡提示将更新已有总结。
- 确认卡必须展示方案与实际差异。
- 确认卡必须展示可能出错的动作归一结果。
- 课前方案和课后实际冲突时，不覆盖课前方案，只标记差异。
- 课后未明确提到的方案动作，状态为 `unknown`，不自动判断完成。

### 11.3 排课确认卡

确认卡必须展示：

- 学员
- 日期
- 开始时间
- 结束时间
- 地点
- 消耗课时
- 课时余额
- 课前训练方案状态
- 时间冲突校验结果
- 课时余额校验结果

产品规则：

- 时间冲突时不允许确认，只能改时间。
- 课时余额小于消耗课时时不允许确认。
- 地点缺失时优先使用学员常用上课地点；学员未配置时必须追问或手动填写。
- 同名学员必须先选择。
- 模糊时间必须追问，例如“下午”不能直接落库。
- 确认后课程状态为已确认。

### 11.4 训练方案确认卡

确认卡必须展示：

- 学员
- 对应课程
- 训练主题
- 热身
- 计划动作
- 注意事项

产品规则：

- 训练方案必须绑定到某节课程。
- 找不到课程时，先追问，不出确认卡。
- 如果该课程已有训练方案，确认卡提示将更新已有方案。
- 第一版不自动生成长期训练周期，只保存单节课方案。

### 11.5 完课确认卡

完课确认卡必须展示：

- 学员
- 对应课程
- 课程时间
- 消耗课时
- 当前剩余课时
- 确认后剩余课时

产品规则：

- 标记完成不是自动扣课时，必须由教练确认。
- 用户确认后，课程状态变为 `已完成`。
- 用户确认后，按该课程的消耗课时生成一条 `完课扣减` 课时变动记录。
- 用户取消后，课程状态和课时余额都不变。
- 当前剩余课时小于消耗课时时不允许确认完成，需要先调整课时或修改消耗课时。

- 长期周期训练计划
- 自动生成复杂训练方案
- 大型专业动作库后台
- 动作视频库

- 动作图片
- 肌肉解剖图
- 自动推荐动作
- 多语言动作同义词
- 动作相似度复杂算法
- 通用健身知识长问答
- 学员分组 / 标签体系
- 复杂 CRM 跟进
- 收费合同
- 体测数据
- 饮食记录
- 复杂图表分析
- 自动续课提醒
- 学员端预约或学员端查看

### 12.2 不做的原因

第一版目标是验证语音驱动的 AI 教练工作台能否成立。范围集中在教练最高频、最能体现解放双手价值的任务上。

## 13. 验收标准、指标、风险

### 13.1 第一版验收标准

1. 教练能用语音完成一次课程训练总结生成。
2. 教练能用语音完成一次排课。
3. 教练能用语音查询今日课表。
4. 教练能查询某个学员的剩余课时和最近课程总结。
5. 语音转写结果先填入输入框，用户可修改后再发送。
6. 每个写入动作都有确认卡。
7. 时间冲突、课时不足、同名学员、学员不存在等场景不会直接写入。
8. AI 不可用或语音失败时，文本输入仍然可用。
9. `日程`、`学员`、`我的` 页面能完成核心兜底操作。
10. 第一版不出现要求学员配合才能完成的主流程。
11. 日程 Tab 支持日视图、周视图、轻量月视图。
12. 周视图顶部展示纯规则统计：本周课程数、已完成课程数、待上课课程数。
13. 手动排课支持自由选择开始时间和结束时间，时间粒度为 15 分钟。
14. 课程详情支持课前训练方案和课程训练总结状态。
15. 课前方案与课后实际存在冲突时，系统保留两份数据并标记差异，不用实际内容覆盖课前方案。
16. 课程训练总结中的每个动作同时保存原始动作名称和标准动作名称。
17. 动作归一不确定时，系统追问或在确认卡中要求教练选择，不强行合并。
18. 训练数据分析、可视化和历史统计基于标准动作名称。
19. 学员详情支持概览、课程、总结、数据、备注五个分区。
20. 学员详情支持手动课时管理和不可删除的课时变动记录。
21. 我的 Tab 支持教练账户展示、默认课时时长配置和动作库管理入口。
22. 我的 Tab 不提供全局默认上课地点；排课地点优先来自学员常用上课地点。
23. 动作库管理支持查看系统默认动作、新增自定义动作、编辑自定义动作、停用自定义动作和添加别名。
24. 课程状态只包含 `已确认`、`已完成`、`已取消`。
25. 课程训练总结状态只包含 `未完成`、`已完成`。
26. 标记完成必须经过完课确认卡，确认后才扣减课时并生成课时变动记录。
27. 课程时长和消耗课时分离，消耗课时取值为 `0.5`、`1`、`1.5`、`2`。
28. 取消课程不扣课时，释放时间冲突，并保留在历史记录中。
29. 剩余课时 `<= 2` 的学员显示 `低课时` 标签。
30. AI 首页只在异常发生时展示语音或 AI 轻量提示，不展示常驻服务状态。
31. 动作库支持按标准动作名称和别名搜索。
32. 长按语音支持上滑取消，首次使用提供轻量引导。
33. 今日状态区不显示待确认 AI 草稿。
34. 周视图空白时间段默认打开手动新建课程，并提供 `问 AI 排课` 二级入口。
35. 语音转写失败后不长期保留原音频。
36. 课程训练总结保存后不允许重新绑定到其他课程。
37. 课后总结缺失强度或完成度时允许保存为 `未填写`。
38. 学员分析第一版只输出基础摘要，不做长期分析报告。
39. 学员数据第一版只做轻量统计，不做复杂图表。
40. 我的 Tab 使用反馈入口采用轻量文本反馈表单，反馈内容必填，联系方式可选。

### 13.2 成功指标

主指标：

> 教练通过语音发起，并最终完成课程训练总结确认保存或排课确认的比例。

次级指标：

- 语音转写成功率
- 转写后手动修改率
- 课程训练总结确认卡确认率
- 排课确认卡确认率
- 完课确认卡确认率
- 课前训练方案填写率
- 动作名称归一成功率
- 动作归一手动修正率
- 学员详情访问率
- 总结未完成标签处理率
- AI 追问后任务完成率
- 辅助页面兜底使用率

体验指标：

- 从开始录音到转写完成的等待时间
- 从发起记录训练到确认保存课程训练总结的总时长
- 从发起排课到确认排课的总时长
- 从打开周视图到完成手动排课的总时长
- 因同名、时间模糊、课时不足导致的阻断次数

### 13.3 风险与产品缓解

| 风险 | 缓解 |
| --- | --- |
| 语音识别错误 | 转写文本先进入输入框，用户可修改后发送 |
| AI 理解错误 | 信息不足时追问，写入动作必须确认 |
| 错误写入业务数据 | 只开放排课、训练方案、课程训练总结三类写入 |
| 课前方案与课后实际冲突 | 保留两份数据并标记差异 |
| 动作名称不统一导致无法分析 | 保存原始名称和标准名称，通过动作库和别名归一 |
| 课时资产误操作 | AI 不允许自动修改课时，课时变动记录不可删除 |
| 完课误扣课时 | 标记完成必须经过完课确认卡，展示扣减前后课时 |
| 首页变成通用聊天 | 默认开场和快捷指令聚焦私教任务 |
